Web Cache Poisoning

Learn how an attacker can manipulate cached responses and cause other visitors to receive unexpected content.

OWASP CWE-436 CAPEC-141

01. What Is Web Cache Poisoning?

Web Cache Poisoning happens when an application stores an incorrect response in its cache.

Another visitor may receive the poisoned response instead of the original safe page.

02. Vulnerable vs Fixed

VULNERABLE CODE

const host = request.headers
    ["X-Forwarded-Host"];
const page = createPage(host);
cache.set("/home", page);

Problem: The application trusts an untrusted host value.

FIXED CODE

const host = TRUSTED_HOST;
const page = createPage(host);
cache.set("/home", page);

Solution: The application uses a trusted host.

05. Why Does It Matter?

If a poisoned response is stored in the cache, other visitors may receive incorrect or manipulated content.

06. How to Prevent It

Use trusted host values and validate request headers. Do not allow untrusted input to control cached responses.
