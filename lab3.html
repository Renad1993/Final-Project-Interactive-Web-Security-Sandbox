Web Cache Poisoning

Learn how attackers manipulate cached responses and cause other visitors to receive unexpected website content.

OWASP A05/span> CWE-436

01. What Is Web Cache Poisoning?

Web Cache Poisoning is a security vulnerability that happens when an attacker causes a web application or cache to store an incorrect or manipulated response.

A web cache stores copies of website responses to make pages load faster. Instead of generating the same response every time, the server can return a previously stored response.

How Does It Happen?

01. Send Request

An attacker sends a request containing an untrusted HTTP header, such as X-Forwarded-Host.

02. Cache Stores Response

The application trusts the untrusted value and generates a response using it. The cache stores that response.

03. Other Visitors

Other visitors may receive the manipulated response from the cache instead of the correct website content.

Important Terms

Web Cache: A system that temporarily stores website responses to improve performance.

HTTP Request: A message sent by a browser to a web server.

Cache Poisoning: When an incorrect response is stored and later returned to other visitors.

Untrusted Header: Request information that should not automatically be trusted by the application.

02. The Vulnerable Line

VULNERABLE CODE

function vulnerableRequest(host) {
    const key = "/home";
    const response = {host: host};
    cache.set(key, response);
    return response;
}

Problem: The application accepts an untrusted host value and stores it in the cache.

The application uses the same cache key /home for different requests. If an untrusted host is included in the response, the cache may store incorrect content.

04. Why Does It Matter?

Web Cache Poisoning can affect more than one visitor. When a manipulated response is stored in a shared cache, multiple users may receive incorrect website content.

Possible Impacts

Misleading Content

Visitors may see incorrect information instead of the original website content.

Website Reputation

Users may lose trust in a website if they receive unexpected or manipulated content.

Multiple Visitors

A single poisoned cached response may affect many visitors who request the same cached page.

Real-World Example

Imagine an online store called TechStore. An attacker manipulates a request so that the application generates a response containing an unexpected website host.

If this response is stored in a shared cache, another visitor may receive the manipulated version when opening the same page.

This can make visitors see content that does not belong to the official website.

05. How to Prevent Web Cache Poisoning

FIXED CODE

function fixedRequest() {
    const host = TRUSTED_HOST;
    const key = "/home";
    const response = {host: host};
    cache.set(key, response);
    return response;
}

Solution: The application uses a trusted host instead of accepting an untrusted value from the request.

Prevention Methods

1. Validate HTTP Headers: Do not blindly trust values received from HTTP headers.

2. Use Trusted Host Values: Use a configured and trusted hostname instead of accepting arbitrary host values.

3. Configure Cache Keys Correctly: Make sure the cache key includes all request values that can change the response.

4. Avoid Caching Unsafe Responses: Do not cache responses that contain untrusted or user-specific information unless handled safely.
